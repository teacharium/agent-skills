# Debugging a lesson preview

The URL from `get_preview_url` renders the saved draft in the real player. Besides looking at it, an agent with a browser tool that can run JavaScript in the page (an "evaluate" or "javascript" tool) can read the player's live state from `window.teacharium`. Use it to check what the screen cannot show: variable values, whether a question registered as correct, which step you are on, and which events and actions fired.

The API exists only on preview pages, not in the editor or in published lessons and embeds. It is read-only: it never changes the lesson or the player, and every method returns a plain JSON copy.

## Waiting for it

The object appears once the lesson and its widgets have loaded. Wait until `window.teacharium?.ready === true` before calling it. If it never appears, the page shows an error instead of the lesson (for example an expired link); read the page text, or get a new URL with `get_preview_url`.

## Methods

| Method | Returns |
| --- | --- |
| `getState()` | Everything below in one object (with the last 20 events). Start here. |
| `getLesson()` | Lesson `id`, `title`, the preview scope (`lessonId`, `stepId` for a single-step preview, `expiresAt`), and every section and step (`id`, `name`). |
| `getCurrentStep()` | The step on screen: `sectionId`, `sectionName`, `sectionIndex`, `stepId`, `stepName`, `stepIndex`, and its `components` (`id`, `type`), matching the ids from `get_step`. |
| `getProgress()` | Lesson `status` (`not_started`, `in_progress`, `completed`), `currentSectionIndex`, `currentStepIndex`, and per-step completion. |
| `getVariables()` | Every variable by name: `value` (current), `initialValue`, `type`, `scope` (`lesson` or `step`). Includes the variables components create, such as a question's correctness and answer. |
| `getItems()` | Every question and assessment item the learner has seen: `widgetId`, `widgetName`, `stepId`, `type` (`instructional`, `practice`, `scored`) and `status` (correct, attempted, attempts, current and max score, current answer). |
| `getHistory()` | `currentIndex` and the step `visits` in order (`stepId`, `sectionIndex`, `stepIndex`, `visitedAt`, `completedAt`). Shows the path a branch actually took. |
| `getWidgetState()` | The saved internal state of each component on the current step, by component id. |
| `getEvents(limit?)` | Recent lesson events, oldest first (up to 200; pass `limit` for the last few): navigation, step starts, actions and widget events, each with `type` and `timestamp`. |
| `help()` | A short text summary of these methods. |

## Example

Run in the page, then interact (click an answer, press Next) and run it again to compare:

```js
JSON.stringify(window.teacharium.getState(), null, 2)
```

Smaller checks:

```js
window.teacharium.getVariables().score?.value
window.teacharium.getCurrentStep().stepName
window.teacharium.getEvents(10).map((e) => e.type)
```

## Tips

- **Reload after edits.** The preview reads saved content when the page loads; reload to see changes, which also resets all state to the start.
- **Debug a branch** by answering the question, then checking `getVariables()` and `getItems()` for the values the condition reads, and `getHistory()` after pressing Next to see which step it went to.
- **An action or button seemed to do nothing?** Check `getEvents()` for the event it should have emitted, and `getVariables()` for the variable it should have set.
- **Check component ids** with `getCurrentStep().components` when a component you added is missing from the screen: if it is listed it rendered but may be hidden or empty; if not, the step content was not saved as you expected (`get_step`).
- Use browser clicks and typing to act as the learner; `window.teacharium` only reads state.
