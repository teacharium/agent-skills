# Teacharium custom CSS guide

## What custom CSS is

Each lesson has one custom CSS stylesheet that is injected into every step, in the editor preview and in the player. Only use it for lesson-wide styling that step and component settings cannot do. Prefer targeting the stable Teacharium selectors (`.teacharium-player`, `.tp-main`, `.tp-content`, `.tp-content__inner`, `.tp-header`, `.tp-footer-wrapper`, `.step--{step-slug}-{orderIndex}`, `.teacharium-step-wrapper`, `.teacharium-grid-layout`, `[data-teacharium-cell="{cellId}"]`, `.teacharium-grid-frame`, `.comp-{componentId}`, `.rich-text-display`) and scope every rule under them. Keep the stylesheet small, and never use it to hide or disable the lesson navigation.

- A lesson has exactly one stylesheet (the "Custom CSS" field in the editor's Lesson Settings). It is injected as a `<style>` block for every step, both in the player (preview, embeds, published lessons) and in the editor's editing canvas and step preview.
- It is not scoped automatically. In the editor the stylesheet sits in the authoring app's page, so an unscoped rule such as `h2 { ... }` also restyles the editor. Always start selectors with one of the hooks below.
- Read it with `get_custom_css`. Change it with `update_custom_css`: `oldStr`/`newStr` for an exact find-and-replace (first match), or `css` to rewrite it. Every write keeps the previous version in the custom CSS history. The limit is 100,000 characters.
- Step and component settings (text styles, frames, backgrounds, the root grid) are the first choice for styling; they show up in the editor's property panels. Use custom CSS for what those cannot do, or for rules that should apply across many steps.

## Stable selectors

These class names and attributes are rendered by the Teacharium player and kept stable. Placeholders are in braces. Get step names and positions from `get_lesson`, and cell and component ids from `get_step`.

| Selector | Matches | Where |
| --- | --- | --- |
| `.teacharium-player` | The whole lesson player. Scope lesson-wide rules (fonts, colors) under it. | Player only |
| `.tp-main` | The player area (header, step, footer). Also carries the current step's class. | Player only |
| `.tp-content` | The area that shows the current step. Also carries the current step's class. | Player only |
| `.tp-content__inner` | The container around one rendered step. | Player only |
| `.tp-header` | The optional header area above the step. | Player only |
| `.tp-footer-wrapper` | The footer with navigation and progress. Restyle it, but never hide it. | Player only |
| `.step--{step-slug}-{orderIndex}` | One step, e.g. `.step--welcome-page-0` for a step named "Welcome Page" at position 0 in its section. The slug is the lowercased name with spaces as hyphens and punctuation removed. | Player and editor preview |
| `.teacharium-step-wrapper` | The wrapper around a step's root grid (step background color and margin). | Player and editor preview |
| `.teacharium-grid-layout` | The step's 12-column root grid. On narrow screens (768px or less) it collapses to one column. | Player and editor preview |
| `[data-teacharium-cell="{cellId}"]` | One root grid cell, by the cell id from the step's root grid (see `get_step`). | Player and editor preview |
| `.teacharium-grid-frame` | A decorative frame drawn behind grid cells. | Player and editor preview |
| `.comp-{componentId}` | The wrapper around one component instance, by its component id (see `get_step`). | Player and editor preview |
| `.rich-text-display` | The rendered markdown of every Text component. | Player and editor preview |

## Example

```css
/* Lesson-wide typography */
.teacharium-player .rich-text-display h2 {
  color: #1d4ed8;
  letter-spacing: 0.01em;
}

/* One step: the step named "Welcome Page", first in its section */
.step--welcome-page-0 .teacharium-step-wrapper {
  background-image: linear-gradient(180deg, #eff6ff 0%, #ffffff 60%);
}

/* One grid cell (cell id "header") on every step that has it */
[data-teacharium-cell="header"] {
  border-bottom: 2px solid #e5e7eb;
}

/* One component instance, by component id */
.comp-Text-1a2b3c {
  font-size: 1.25rem;
}
```

## Cautions

- **Never hide or disable navigation.** Do not hide, cover or shrink `.tp-footer-wrapper`, its Next/Previous buttons, or the start button, and do not use CSS to hide content a learner needs to answer a question.
- **Scope every rule.** Never style `html`, `body`, `:root` or bare element selectors (`h1`, `p`, `button`) on their own.
- **Keep it small.** A few targeted rules are easier for the author to maintain than a theme. Avoid `!important` unless a rule must beat an inline style, and avoid `position: fixed` and long-running animations.
- **Per-step and per-component hooks are fragile.** A step's class contains its name and position, so renaming or reordering the step changes it. Component ids change when a component is deleted and re-added or a template is applied. Update the stylesheet after such changes.
- **Check small screens.** At 768px wide and below the root grid collapses to one column; do not fight that with fixed widths.
- **Preview the result** with `get_preview_url` (a step or the whole lesson).
