## Example 1: build a three-step intro section

User: "Add an intro section to my Photosynthesis lesson for 5th graders: a hook, the key vocabulary, and a quick check."

1. Find the lesson and read its context.

   ```text
   list_lessons { "search": "Photosynthesis" }
   get_lesson { "lessonId": "<lesson id>" }
   ```

   Read the abstract and existing sections. Note the variables and recent templates.

2. Load the rules and the catalog.

   ```text
   get_authoring_guide { "topic": "step-content" }
   list_components { "lessonId": "<lesson id>" }
   list_templates { "search": "intro" }
   ```

   The catalog decides which question component to use for the check (for example a multiple choice widget, if listed).

3. Create the structure. Younger learners get short steps, one idea each.

   ```text
   create_section {
     "lessonId": "<lesson id>",
     "name": "Introduction",
     "stepNames": ["Why plants need light", "Key words", "Quick check"]
   }
   reorder_sections { "lessonId": "<lesson id>", "sectionIds": ["<intro id>", "...existing ids"] }
   ```

4. Build the hook step: a two-column layout with text on the left and an image on the right.

   ```text
   get_step { "stepId": "<hook step id>" }            -> keep updated_at
   configure_root_grid {
     "stepId": "<hook step id>",
     "expectedUpdatedAt": "<updated_at>",
     "cells": [
       { "id": "text", "row": 1, "col": 1, "rowSpan": 12, "colSpan": 7 },
       { "id": "picture", "row": 1, "col": 8, "rowSpan": 12, "colSpan": 5 }
     ]
   }
   add_components {
     "stepId": "<hook step id>",
     "expectedUpdatedAt": "<updated_at from the previous result>",
     "cellId": "text",
     "components": [
       { "type": "Text", "props": { "content": "## Where does a tree get its food?\n\nPlants do not eat. So how do they grow?" } }
     ]
   }
   add_components { "stepId": "<hook step id>", "cellId": "picture", "components": [ { "type": "<image component from list_components>", "props": { ... } } ], ... }
   ```

5. Build the vocabulary step with a single `Text` component, then the quick check: add the question component first (it creates item variables such as `correct`), then any `Text` that reads those variables through `<StringExpression />` or `<NumericExpression />`.

6. Preview and fix.

   ```text
   get_preview_url { "stepId": "<quick check step id>" }
   ```

   Open the URL with a browser tool (or hand it to the user). If text overflows a cell or a question is unclear, adjust with `edit_component` or `configure_root_grid`.

7. Keep the abstract in sync.

   ```text
   update_abstract {
     "lessonId": "<lesson id>",
     "oldStr": "## Sections",
     "newStr": "## Sections\n\n### Introduction\n- Why plants need light: hook question with a picture\n- Key words: chlorophyll, glucose, carbon dioxide\n- Quick check: one multiple choice question"
   }
   ```

8. Report: "Added an Introduction section with three steps (Why plants need light, Key words, Quick check) and updated the abstract."

## Example 2: revise an existing quiz step

User: "In the Fractions lesson, make question 3 harder and give better feedback for wrong answers."

1. Locate the step by name.

   ```text
   get_lesson { "lessonId": "<lesson id>" }       -> find "Question 3" in the Quiz section
   get_step { "stepId": "<question 3 id>" }      -> keep updated_at, read the outline
   list_components { "lessonId": "<lesson id>", "components": ["MultipleChoice"] }  -> field definitions for the question component
   ```

   The outline lists the question component's ID, its choices, and the nested `Text` components inside each choice, with their paths.

2. Change only what was asked. Edit the prompt text and the choices in place; keep the layout, styles, and scoring settings.

   ```text
   edit_component {
     "stepId": "<question 3 id>",
     "expectedUpdatedAt": "<updated_at>",
     "id": "<prompt Text id>",
     "updates": { "content": "Which fraction is **closest** to 1/2?" }
   }
   edit_component {
     "stepId": "<question 3 id>",
     "expectedUpdatedAt": "<updated_at from the previous result>",
     "id": "<question component id>",
     "updates": { "choices": [ ...every choice, with new feedback on the wrong ones... ] }
   }
   ```

   Array props such as `choices` are replaced as a whole, so send every entry, keeping each existing choice's `id` and nested `content`. To change the text inside a choice, edit that nested `Text` component by its own ID instead.

3. If a write fails with a conflict, someone saved the step in the meantime: `get_step` again, re-apply the edit to the new content, and retry. If it fails because the lesson is locked by another author, stop and tell the user who has it open.

4. Preview with `get_preview_url`, check the question and each feedback message, and fix anything that reads wrong.

5. Nothing structural changed, so the abstract only needs an update if it describes this question's content.

6. If the user dislikes the result, `get_step_history` lists earlier versions; after the user confirms, `restore_step_version` with `confirm: true` brings one back.
