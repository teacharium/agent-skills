# Teacharium custom field types

Field definitions from `list_components` use these custom types. Each entry gives the value format to write into the component's props.

## Custom Field Types

**imageMedia** - Image from the media library
- Value format: string, `"media:<id>"` (an id from the media library)
- Example: `"media:3f1c2b9e-8a4d-4c7e-9b21-5d6e7f8a9b0c"`

**videoMedia** - Video from the video library
- Value format: string, `"video:<id>"` (an id from the video library)
- Example: `"video:7a2d4e6f-1b3c-4d5e-8f9a-0b1c2d3e4f5a"`

**audioMedia** - Audio from the media library
- Value format: string, `"media:<id>"` (an id from the media library)
- Example: `"media:9c8b7a6d-5e4f-4a3b-8c2d-1e0f9a8b7c6d"`
- Never invent ids: use ids you were given or found in the media library, or leave the field empty.

**numericExpression** - Numeric value or variable expression
- Value format: string (can contain variables or plain numbers)
- Examples:
  - `"5"` - Plain number as string
  - `"{{score}}"` - Variable reference
  - `"{{totalPoints}} + 5"` - Variable reference with arithmetic
- Important: Always use strings, not numbers. Variables must be wrapped in `{{}}`

**stringExpression** - String value or variable expression
- Value format: string (can contain variables or plain text)
- Examples:
  - `"Hello World"` - Plain text
  - `"{{userName}}"` - Variable reference
  - `"Welcome {{firstName}}"` - Mixed text and variable

**action** - One or more Teacharium actions to execute
- Value format: array of action configuration objects
- Each action object has:
  - `actionType`: string (the type of action to execute)
  - `parameters`: object (action-specific parameters)
- Example:
```json
[
  {
    "actionType": "setVariable",
    "parameters": {
      "variableName": "score",
      "value": 100
    }
  },
  {
    "actionType": "showFeedback",
    "parameters": {
      "message": "**Great job!**",
      "variant": "correct",
      "showNextButton": true
    }
  }
]
```
- See the Actions section below for all available action types

**variable** - Reference to a lesson variable
- Value format: string (variable name without {{}})
- Example: `"score"`, `"userName"`, `"currentQuestion"`
- Used for: Component properties that need to reference a specific variable

**placeholder** - Placeholder text or temporary content marker
- Value format: string
- Example: `"Enter your name"`, `"Coming soon"`
- Used for: Temporary content markers or placeholder text in component structures

**condition** - Boolean expression for conditional logic
- Value format: object with an `expression` string
- Structure:
  - `expression`: string - A freeform boolean expression evaluated by mathjs
- Expressions use `{{variableName}}` for variable references and support:
  - Comparison operators: `>`, `<`, `>=`, `<=`, `==`, `!=`
  - Logical operators: `and`, `or`, `not`
  - Parentheses for grouping
  - Built-in functions: `contains(haystack, needle)`, `not_contains(haystack, needle)`
- Examples:
```json
{ "expression": "{{score}} >= 80" }
```
```json
{ "expression": "{{score}} >= 80 and {{attempts}} > 0" }
```
```json
{ "expression": "contains({{userName}}, \"John\")" }
```
```json
{ "expression": "not ({{isLocked}} == true)" }
```
- Used for: Component properties that control conditional behavior, visibility, or branching logic

### Voiceover Field

**voiceover** - Text-to-speech audio configuration
- Value format: object with the following properties:
  - `enabled`: boolean - Whether voiceover is enabled
  - `voice`: string - Voice to use (e.g., "alloy", "echo", "fable", "onyx", "nova", "shimmer")
  - `showPlayButton`: boolean - Whether to show a play button
  - `content`: string - The script text (optional, usually set by resolveData)
  - `contentHash`: string - Hash of the script (optional, usually set by resolveData)
  - `cached`: boolean - Whether the audio is cached (optional, usually set by resolveData)
- Example:
```json
{
  "enabled": true,
  "voice": "alloy",
  "showPlayButton": false
}
```
- Note: The `content`, `contentHash`, and `cached` fields are managed automatically by the editor, which also generates the audio. The audio itself is generated by the Teacharium editor when the component is selected there (its voiceover field generates it); a voiceover set up outside the editor (e.g. through the MCP tools) stays silent until someone opens the step in the editor and selects the component

**color** - Color picker for selecting a color value
- Value format: string (CSS color value)
- Examples: `"#FF5733"`, `"#000000"`, `"rgba(255, 87, 51, 0.5)"`
- Used for: Component properties that need a color selection (backgrounds, text colors, borders, etc.)

**svgSource** - Inline SVG markup (used by the `Svg` component)
- Value format: string containing one complete `<svg>…</svg>` document. The markup is stored on the component itself; it is not a media library id.
- Always include `xmlns="http://www.w3.org/2000/svg"` and a `viewBox`; the graphic then scales to the width of its grid cell. Omit `width`/`height` on the `<svg>` element.
- Variable substitution: write `{{variableName}}` anywhere in the markup (attribute values or text content). It is replaced with the variable's current value and re-rendered whenever the variable changes. Values are HTML-escaped, so they are safe in attributes and text.
- Conditionals: `{{#if flag}}…{{else}}…{{/if}}` and `{{#unless flag}}…{{/unless}}` show or hide whole elements (truthy test only; no comparisons).
- No arithmetic inside the markup. Pick viewBox units so a variable's value can be used directly (e.g. viewBox width 100 for a 0-100 percentage), use `transform="scale({{ratio}})"` / `rotate({{angle}})`, or have actions store a precomputed value in a variable.
- Use `currentColor` for strokes/fills that should follow the lesson's text color; prefer presentation attributes (`fill`, `stroke`, `font-size`) over `<style>` blocks.
- Removed when rendered: `<script>`, `<foreignObject>`, `<iframe>`/`<embed>`/`<object>`, `on*` event attributes, and links other than `#id`, http(s) or raster `data:image/…` URLs. Use action-driven components for interactivity.
- Ids (gradients, clip paths, markers) are automatically prefixed per component, so reusing `id="grad"` in several Svg components is fine; reference them normally with `url(#grad)` or `href="#grad"`.
- Keep markup hand-authored and compact (a few KB); do not embed traced bitmaps.
- Example (bar that fills to `percent`, labeled with `playerName`, star when `passed` is true):
```json
"<svg xmlns=\"http://www.w3.org/2000/svg\" viewBox=\"0 0 100 30\"><rect x=\"0\" y=\"10\" width=\"100\" height=\"10\" rx=\"5\" fill=\"#e5e7eb\"/><rect x=\"0\" y=\"10\" width=\"{{percent}}\" height=\"10\" rx=\"5\" fill=\"#22c55e\"/><text x=\"0\" y=\"7\" font-size=\"6\" fill=\"currentColor\">{{playerName}}: {{percent}}%</text>{{#if passed}}<text x=\"94\" y=\"7\" font-size=\"6\">★</text>{{/if}}</svg>"
```

**step** - Reference to a specific lesson step
- Value format: string (the step's id, a uuid from the lesson structure)
- Example: `"3fb62e1a-3812-46d4-8fd6-7749857f9d03"`
- Used for: Navigation or step-specific logic

**textStyle** - Text styling (Text component)
- Value format: object; every key is optional:
  - `color`: string - CSS color of the text (default "#000000")
  - `effect`: "none" | "glow" | "outline" | "3d" | "neon" | "vintage" | "gradient-rainbow" | "gradient-sunset" | "gradient-ocean" | "gradient-fire" | "gradient-purple" | "emboss" | "retro" | "comic" | "elegant" | "techno" | "stamp"
  - `textShadow`: { `size`: "none" | "small" | "medium" | "large", `color`: string, `offsetX`: number, `offsetY`: number, `blur`: number }
- Example: `{ "color": "#1d4ed8", "effect": "glow" }`

**frame** - Border, background and layout of a component's wrapper (available on every visual component)
- Value format: object; every key is optional (defaults in parentheses):
  - `borderStyle`: "none" | "solid" | "dashed" | "dotted" ("none"); `borderWidth`: number in px (2); `borderColor`: CSS color ("#000000")
  - `shadowType`: "none" | "small" | "medium" | "large" ("none")
  - `cornerRadius`: "none" | "small" | "medium" | "large" | "circle" ("none")
  - `backgroundColor`: CSS color; `backgroundGradient`: CSS gradient string; `backgroundImage`: "media:<id>" (an image wins over a gradient, which wins over a color)
  - `backgroundSize`: "cover" | "contain" | "auto" ("cover"); `backgroundPosition`: "center" | "top" | "bottom" | "left" | "right" ("center"); `backgroundRepeat`: "no-repeat" | "repeat" | "repeat-x" | "repeat-y" ("no-repeat")
  - `padding`, `margin`: number in px (padding is automatic, 16px, when a border, shadow or background is set)
  - `tilt`: "none" | "left-small" | "left-large" | "right-small" | "right-large" ("none")
  - `widthBehavior`: "full" | "fit-content" ("full")
- Example: `{ "borderStyle": "solid", "borderColor": "#94a3b8", "cornerRadius": "medium", "backgroundColor": "#f8fafc" }`

Actions are documented separately (see [actions.md](actions.md)).

## Guidelines for Custom Fields

1. **Always use the correct value type** - numericExpression and stringExpression must be strings, not numbers or raw text
2. **Variable syntax** - When referencing variables in expressions or conditions, always use `{{variableName}}` format
3. **Media fields** - Use only media ids you were given or found in the media library; never invent one
4. **Actions** - When using action fields, ensure the actionType matches available actions and parameters are valid
5. **Voiceover** - When enabled, the script content is usually provided in a separate field (like `script` in Voiceover component)
6. **SVG** - svgSource values are full `<svg>` strings with a viewBox; substitute variables with `{{variableName}}` directly in the markup
7. **Conditions** - Must be objects with an `expression` string field. Use `{{variableName}}` for variable references and comparison/logical operators
